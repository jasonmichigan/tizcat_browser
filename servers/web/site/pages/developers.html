A platform built to change quickly

A complete browser takes hours to rebuild, so TizCat keeps only small, permanent hooks in the browser. Everything likely to change lives in a module, copied in at every start, or on a server, deployed in seconds, one part at a time.

PartWhere it runsUpdates
Websitewww.tizcat.comin seconds, on its own
Accountsaccount.tizcat.comin seconds, on its own
Front doorapi.tizcat.comin seconds, on its own
Ads, Rewards points, JibWalletbehind api.tizcat.com, unreachable from the internetin seconds, each on its own
Live settingsa settings store at the edgein seconds, with nothing redeployed
TizCat Services, Yuzalinside TizCat, as built-in moduleswith a restart of TizCat
Browser hooksTizCat itselfwith a rebuild, rarely

The parts agree through a written, versioned contract: every request each server accepts is defined once, the servers check against it, and so do the tests. A change that keeps the contract is safe for every part; a change that breaks it becomes a new version, with the old one kept until nothing uses it.

Public calls

api.tizcat.com/v1

  • GET /v1/health: each service's version and state
  • GET /v1/config: the public settings TizCat uses
  • GET /v1/ads/catalog: the ads currently running
  • GET /v1/wallet/info: JibWallet and JibCoin's state

Full API documentation is coming. Security reports and developer questions: hamid@tizcat.com.

Security, by default

  • HTTPS everywhere, certificates renewed automatically, plain http redirected
  • HSTS for a year on tizcat.com and every subdomain
  • A strict content security policy on every page; no framing by other sites
  • Account passwords stretched with 600,000 rounds in the browser; only a secret-keyed check value is stored
  • Links that lead elsewhere follow only tizcat.com addresses
